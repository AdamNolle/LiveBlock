A different layer
of control.

Browser blockers work inside a page. LiveBlock experiments at the display capture layer, where a person can mark a screen region for local fill. Behavior depends on operating-system capture and overlay permissions.

02 / Inside the projectFrom screen to overlay

Everything happens
close to home.

LiveBlock is built around a local pipeline. Source builds expose more experimental tools; release packages are still gated.

  1. 01

    Capture locally

    Desktop capture frames feed the app's local processing path, subject to platform permissions and protected-content limits.

  2. 02

    Choose a region

    Draw a manual region around something you want covered. Regions persist in normalized screen coordinates.

  3. 03

    Fill from context

    Mirror-blend fill uses neighboring pixels. The experimental detector can suggest regions, but its model has not passed release quality gates.

LOCAL BY DESIGN

03 / PlatformsDesktop exploration

One idea.
Different desktops.

macOS

Native Swift, ScreenCaptureKit, CoreML, and an AppKit overlay.

Windows

Experimental Tauri port with Windows Graphics Capture and local ONNX processing.

Linux

Experimental Tauri port with portal/PipeWire or X11 capture, depending on the session.

Platform capabilities and real-device validation differ. See the release matrix ↗ for the intended scope and open evidence.

Current state / experimental

LiveBlock is an active source project. No production-ready package or promoted detector is available. Signing, model quality, and real-device release checks remain open.
